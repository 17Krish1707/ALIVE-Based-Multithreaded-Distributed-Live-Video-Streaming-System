Distributed Clock Algorithm Comparison

Cristian's Algorithm

Physical Clock
  • Type: Physical Clock Synchronization
  • Coordinator: Authoritative Time Server (VTS)
  • Key Principle: Client requests time, measures RTT, estimates one-way propagation delay as RTT / 2, and applies correction T_server + RTT/2 - T_client.
  • Limitation: Vulnerable to single point of failure (server) and asymmetric network route delays.

Berkeley Algorithm

Physical Clock
  • Type: Physical Clock Synchronization
  • Coordinator: Internal Coordinator (VTS)
  • Key Principle: Coordinator periodically polls all distributed nodes, collects their local clock times, computes the collective average, and distributes individual delta adjustments.
  • Advantage: No external UTC server needed; achieves consensus among participating nodes.

Lamport Logical Clock

Logical Clock
  • Type: Logical Counter (Causality Ordering)
  • Coordinator: None (Decentralized)
  • Key Principle: Orders distributed events without physical time. Local event increments L = L + 1. Message receipt updates L_recv = max(L_recv, L_msg) + 1.
  • Distinction: Never changes operating system or simulated physical clocks.

Resource Ordering: Forces both workers to lock Peer-1 first, then Edge-1. Worker-2 blocks until Worker-1 releases Peer-1. No deadlock.
